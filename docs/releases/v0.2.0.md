# LearnHarness Server v0.2.0

One read-only operator config file replaces three configuration channels, plus fixes for regressions in the port from upstream. Chat, graph and settings data formats are unchanged; upgrade by rebuilding the image and moving the configuration (below).

## Breaking changes

- **One config file.** `LH_CONFIG_FILE` (`/secrets/config/config.json` in the image, repo-root `config.json` in development) holds `keys`, `customProviders` and `claudeCode`. It replaces:
  - `LH_AUTH_FILE` / `auth.json`: its entries move unchanged into `"keys"`;
  - `LH_CUSTOM_PROVIDERS`: the array moves into `"customProviders"`;
  - `"claudeCode": {"enabled": true}` in `data/settings.json`: it moves into the config file. The old settings entry is dropped automatically.

  `LH_AUTH_FILE` and `LH_CUSTOM_PROVIDERS` are no longer read; the server logs a warning if either is set. Real environment variables still win over `keys`. The app never writes the file and picks up edits (keys, custom providers, Claude Code) without a restart. Step-by-step migration: [deploy/README.md](../../deploy/README.md#upgrading-from-01x); template: [deploy/config.example.json](../../deploy/config.example.json).
- The Docker deployment mounts a **directory** holding only the config (`./secrets/config:/secrets/config:ro`), not the file, so rename-style saves are seen without a restart. Never put `runtime.env` in that directory.
- `{"env": "NAME"}` references in `customProviders` may not name `LH_*` or `NODE_*` variables; a file that does is ignored as a whole.
- Links with `?prompt=` prefill the composer instead of sending; press Enter to send.
- Custom models need `"input": ["text", "image"]` to receive images and to be offered for the Vision slot. The removed in-app custom provider allowed images for every custom model.

## Security

- Agent `find`/`grep` globs and vault skip patterns use a non-backtracking matcher. A crafted pattern could freeze the server for seconds to minutes; matching is now linear in pattern and path length.
- Demo verification in headless Chrome refuses requests to the server's own networks: loopback, private and link-local ranges, CGNAT/tailnet `100.64.0.0/10`, non-global IPv6, single-label hosts, `*.internal`, `*.local` and `*.ts.net`. WebRTC cannot open non-proxied UDP, and Chrome starts with a scrubbed environment instead of the server's (gate token, provider keys). Public CDNs stay reachable. DNS rebinding and WebSocket handshakes are not covered; use a container egress policy for full isolation.
- A cross-site `?prompt=` link can no longer send a message on the owner's behalf; it only prefills.
- Vault scans and note extraction read the opened file descriptor: a note swapped for a symlink or FIFO during a scan is skipped, and extraction checks the descriptor's real path stays inside the vault.
- The Providers page never shows a mask of a real `LH_*` or `NODE_*` environment variable, even when the config file lists a key with that name.
- Config file errors hide field names that do not look like identifiers, so a secret pasted as a field name is not echoed to the log or the Providers page.
- `{"env"}` references cannot send the access token or other `LH_*`/`NODE_*` settings to a custom provider.
- The config file is re-read only when its identity is stable across the read, so an in-place write caught midway is retried.
- The `LH_TAILSCALE_USERS` code comment now states the real requirement: only the Serve proxy may reach the listener.

## Performance

- The vault poll reuses a note's content hash while its size, modification time and inode are unchanged, so a 30 s poll no longer reads and hashes every note. With auto-extract on, a poll scans the vault once instead of twice.
- A vault scan writes `sources.json` once per scan instead of once per changed note.
- The activity feed and the stale-job sweep read the jobs folder once instead of once per chat.
- Chat list summaries are cached by file size and modification time, so the sidebar, activity feed and graph views no longer parse every chat record on each refresh.
- The graph view reads `sources.json` once per request and takes session titles from the cached summaries.
- **Layout:** when the graph already has positions, the settle after each extraction merge runs 60 force-layout ticks instead of 300 (about 5× less blocking per merge). The first layout of a graph still runs 300. Settled layouts may differ slightly from 0.1.x.
- Hashed `/_next/static/` files are cacheable (Next's `immutable`), and the bundled fonts are cached privately for a year; every other response stays `private, no-store`. Full page loads no longer re-download the client bundle.
- The coverage ring polls a new `GET /api/chats/:id/coverage` instead of the full chat record, and the chat route no longer parses the record twice for coverage.
- Key lookups skip the environment mirror when neither the config file nor any managed variable changed; the providers list and cost folds read the config once per request.
- The example compose health check runs every 120 s instead of 30 s.

Known, not addressed in this release:

- Headless Chrome is launched once per demo run, not once per demo job.
- Graph ledgers are re-read and re-parsed on every read.
- Every chat mutation rewrites the whole record, including its image pool.
- Plugin agent sessions and worker tasks stay in memory for the life of the process.
- The turn stream sends the whole partial message about every 100 ms, so long replies cost bandwidth quadratic in their length.

## Fixes

- An invalid config file (bad JSON, unknown field, duplicate or reserved provider id) is ignored as a whole: environment keys and built-in providers keep working, the error is logged once, and the Providers page shows it.
- Custom provider `{"env": "NAME"}` secrets resolve from the environment first, then from the config file's `keys`.
- `CLAUDE_CODE_OAUTH_TOKEN` may live in the config file's `keys`; it is the only config-file key passed to the Claude Code CLI.
- Model pins on retired upstream providers (`chatgpt`, `*-subscription`, `custom`) left in migrated settings are refused with the "Set up providers" prompt instead of a bare 503. Background jobs with such a pin now fail cleanly with a reason instead of hanging in `running`.
- The Claude Code CLI again receives Bedrock/Vertex routing (`AWS_*`, `GOOGLE_*`, `CLOUD_ML_REGION`), `XDG_*`, `USER` and `SHELL`; `PATH` is matched case-insensitively.
- Missing-key and Claude Code refusals point at the server config file, not the removed in-app editors.
- Custom providers can use plain HTTP on private IPv4 ranges, a Docker service name, or `host.docker.internal`. Public hosts still require HTTPS.
- Key entries starting with `__` (carried over from upstream) are hidden, and `CUSTOM_OPENAI_API_KEY` is shown fully redacted and never copied into the process environment.
- The model catalog and the Providers page re-read the server when the tab regains focus (at most every 30 s), so config file edits show up without a reload.
- `scripts/smoke-opening-prompt.mjs` and `scripts/smoke-learner-images.mjs` configure the web-access gate and send credentials.
