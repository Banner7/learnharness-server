# LearnHarness Server v0.1.0

First release as its own project. LearnHarness Server is a self-hosted, browser-only build of [LearnHarness](https://github.com/amosblomqvist/learnharness) by Amos Blomqvist, rebased on upstream **v0.6.0** and shipped as a Docker image. It is used from a desktop browser or a phone; there is no desktop app.

## What's new since the previous 0.4.1-based builds

The previous builds (versions `0.4.x-banner.N`) were based on upstream 0.4.1. This release is a fresh port onto upstream 0.6.0, which brings in upstream's work since then, including:

- Flashcards with FSRS-6 scheduling.
- Side conversations.
- The core plugin set: Flashcards, Coding Questions, Drawing Pad, and Rich code blocks.
- The plugin API v1 and authoring kit.
- Upstream's teaching, practice, graph, compaction, and accounting changes.

The server features from the earlier builds were reimplemented on top of 0.6.0:

- Fail-closed access gate (`LH_WEB_ORIGIN`, `LH_WEB_ACCESS_TOKEN`, optional `LH_TAILSCALE_USERS`).
- Vault library that follows a read-only Markdown folder (`LH_VAULT_DIR`, `LH_VAULT_EXCLUDE`).
- Phone-first layout and the Kasumi look, now with an Automatic theme that follows the system light/dark setting.
- Claude Code through the CLI pinned in the image.

New in this line:

- Any number of OpenAI-compatible providers through `LH_CUSTOM_PROVIDERS`, with secrets referenced by environment variable name.
- Read-only Providers page: credentials come only from the server. Hand edits to `auth.json` take effect without a restart.
- Hardening: the agent's file tools cannot read the Claude CLI config, `/proc` or `/sys`; `/secrets` is mounted read-only; Coding Questions runs tests with a minimal environment; vault notes are opened without following symlinks and capped at 2 MiB (larger notes stay listed but are not extracted); every response carries `X-Content-Type-Options: nosniff`.

## Differences from upstream

- Server only. No Electron app, installers, or in-app updater.
- Every request is refused until the access gate is configured. Access is by HTTP Basic auth (user `learnharness`) or an allowlisted Tailscale identity, with `Host` and `Origin` pinned to the configured origin.
- Credentials come only from server environment variables or a read-only `auth.json`. No in-app key entry, and no ChatGPT, GitHub Copilot, or Grok sign-in.
- `LH_CUSTOM_PROVIDERS` replaces the in-app custom endpoint editor.
- Claude Code is enabled out of band in `data/settings.json`.
- Files on the browser's device cannot be attached; the agent reads paths on the server.
- Phone-first layout and Kasumi default look.

## Breaking changes

- **A fresh data directory is required.** Data from the 0.4.1-based builds (chats, graph, settings, imported sources) is not migrated and must not be mounted as `LH_DATA_DIR`.
- Keys saved in the app are no longer supported. Move them to environment variables or to a flat `{"VAR": "value"}` `auth.json` at `LH_AUTH_FILE`.
- `LH_ALLOWED_HOSTS` and `CUSTOM_OPENAI_API_KEY` are removed. Use `LH_WEB_ORIGIN` and `LH_CUSTOM_PROVIDERS`.
- Subscription sign-in connections are removed.

## Upgrade and deploy

1. Back up the old deployment's data directory and keep the old image for rollback.
2. Build the image: `docker build -t learnharness:0.1.0 .`
3. Create new, empty `data/` and `claude/` directories (`chown 1000:1000 claude`), and `secrets/runtime.env` with at least `LH_WEB_ORIGIN` and `LH_WEB_ACCESS_TOKEN` (`openssl rand -hex 32`), plus your provider keys.
4. Start from `deploy/compose.example.yml`. Keep the port on loopback and put an authenticated HTTPS proxy (for example Tailscale Serve) in front.
5. Optional: mount a notes folder read-only and set `LH_VAULT_DIR`; set `CLAUDE_CODE_OAUTH_TOKEN` and add `"claudeCode": {"enabled": true}` to `data/settings.json`.
6. `docker compose up -d`, sign in, and choose Strong, Cheap, and Vision models in Settings.

See [deploy/README.md](../../deploy/README.md) for details.

## Known limitations

- The image is amd64 only, because Chrome for Testing publishes no linux-arm64 headless shell.
- The access gate is for a single owner; it is not multi-user hosting.
- Coding Questions runs code on the server without a sandbox, and community plugins run inside the server process. Install only code you trust.
- Custom providers have no model discovery and no pricing; list each model with its limits.
- The plugins' native and isolated test harnesses were removed; they targeted upstream's Electron host.
- The Automatic theme card previews only the light colors.
- The build fetches fonts from Google Fonts through `next/font`, so it needs network access.
