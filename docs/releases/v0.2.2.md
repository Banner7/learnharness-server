# LearnHarness Server v0.2.2

Voice dictation (Deepgram) is removed, and two phone layout fixes land. The only breaking change is in the plugin API. Upgrade by rebuilding the image.

## Breaking for plugins

- Removed from the plugin API: `mountDictation`, `PluginDictationProps`, `PluginDictationHandle`, the `dictation` prop of `mountStandardComposer`, and the optional `appendTranscript` hook on question and problem editor handles. Community plugins that use them must drop those calls before upgrading.

## Dictation removed

- The Dictate button and its recording meter are gone from every composer and dock and from the side conversation.
- Removed with it: the `mod+d` "Toggle dictation" shortcut, the `/api/stt/token` route, the audio worklet, the `dictation` settings section, the Settings → Providers dictation language picker, and the `DEEPGRAM_API_KEY` key entry.
- A stored `dictation` section in `data/settings.json` is preserved verbatim by the settings sanitizer — unknown top-level keys ride along untouched — but no code reads it, so it is inert.
- The device keyboard's own dictation still works in any text field.

## Fixes

- Phone, home screen with a non-empty graph: the node search box overflowed left over the sidebar button. Home node search is now hidden below 640 px; search from Chains instead.
- Phone, Chains top bar: the close button is no longer clipped at 390 px.
- The Dictate button no longer collapses to a sliver in the row under the composer (it is gone with dictation).

## Upgrade notes

- `DEEPGRAM_API_KEY` in `runtime.env` or in the config file's `keys` is now unused and can be deleted. The config file accepts any environment-style name under `keys` — the schema validates each name against `^[A-Za-z_][A-Za-z0-9_]*$` and its string value — so a leftover `DEEPGRAM_API_KEY` entry parses cleanly and is simply never read.

## Verified

Typecheck and lint clean; full suite 4,631 tests (the SDK grading type test timed out under load and passed alone); UI Showcase plugin tests; production build. Checked in headless Chromium at 390 × 844 against the production build: no horizontal overflow on home, a chat and a new session; the sidebar button is the top element at its position; the Chains close button ends at 378 px. Desktop positions at 1280 px are unchanged. Not checked on a real phone; the plugin browser smoke scripts were edited but not run.
